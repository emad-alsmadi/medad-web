# برومبت بدء التنفيذ — ترحيل الأدوار والصلاحيات (RBAC)

> انسخ كل ما تحت الخط كما هو والصقه في Claude Code داخل مجلد المشروع.
> **قبل اللصق:** احفظ دليل الـ API الجديد في `api/API_INTEGRATION.md`، وشغّل الـ Backend على `http://localhost:8080`.

---

أنت تعمل على `medad-web`: واجهة React 18 + Vite + TypeScript + TanStack Query، عربية بالكامل RTL، لنظام حكومي لإدارة الضبوط الشرطية. الفرع `develop`.

## المهمة

نفّذ **المراحل 0 إلى 4** من الخطة `docs/plans/rbac-implementation-plan.md`: التحقق من العقد، الأنواع ونواة الصلاحيات، مصدر الهوية من `/users/me`، الحرّاس والمسارات، واستبدال فحوص الدور. ثم **توقّف** وأبلغني قبل المرحلة 5.

## لماذا

الـ Backend انتقل من دورين نصيين ثابتين (`'ADMIN' | 'USER'`) إلى أدوار ديناميكية:

- `role` صار كائناً `{ id, name, builtIn }`.
- الصلاحيات تصل في `permissions: Record<Resource, Action[]>`، مع `GET /users/me`.

الواجهة الحالية تتخذ قرارات التفويض بـ`user.role === 'ADMIN'` في 14 ملفاً. بعد نشر الـ Backend ستصبح هذه المقارنة `false` للجميع، فيختفي الـ Dashboard عن المدير وتظهر تسميات الأدوار فارغة. **هذا ترحيل إلزامي، وليس ميزة اختيارية.** المراحل 0–4 هي الحد الأدنى الذي يجعل التطبيق يعمل مع الـ Backend الجديد، لذا تأتي أولاً وتُدمج معاً.

3. من `api/API_INTEGRATION.md`: الأقسام 2.2، 2.4، 4 (كله)، 5، و8 (الأنواع). لا تقرأ بقية الدليل؛ التقارير والنماذج والإحصائيات منفّذة ومطابقة.

لا تقرأ المستودع كله. اتبع: بحث ← تحديد ← قراءة ← تنفيذ ← تحقق.

## ما هو صحيح أصلاً — لا تلمسه

- `src/lib/api/client.ts`: عميل `fetch` واحد، وتجديد التوكن عند `401` مرة واحدة مع single-flight. لا يُخرج المستخدم عند `403`، وهذا صحيح. التعديل الوحيد المسموح فيه هو رسالة «تم تعطيل حسابك» (المرحلة 2).
- الجلسة في كوكيز عبر `lib/session` و`lib/cookies`. **تجاهل مثال Axios و`localStorage` في القسم 9 من الدليل**، فهو يخالف معمارية المشروع.
- `VITE_API_BASE_URL` يبقى باسمه، ولا تستخدم `VITE_API_URL`.
- `AuthProvider` يمرّر قيمة مُذكَّرة بـ`useMemo`، والتعليق هناك يشرح حلقة إعادة توجيه لا نهائية حدثت سابقاً. حافظ على ذلك.

## القرارات المحسومة (التفاصيل في الخطة)

- **D1:** `useSession()` يجلب `GET /users/me`، والكوكي `initialData` فقط، مع `staleTime` 5 دقائق و`refetchOnWindowFocus`. مصدر واحد للبيانات، لا مفتاحان.
- **D2:** دالة نقية `can(permissions, resource, action)` في `lib/auth/permissions.ts`، وhook `useCan()`. لا تتخذ قرار تفويض بـ`builtIn` أبداً.
- **D3:** `RequirePermission` يحل محل `RequireRole`، ثم يُحذف `require-role.tsx`.
- **D4:** `/` يوجّه إلى أول صفحة مسموحة حسب الترتيب في الخطة، والملف الشخصي هو الملاذ الأخير. يجب ألا تحدث حلقة إعادة توجيه.
- **D5:** الـ Dashboard يحتاج `REPORTS:VIEW`. بطاقتا المستخدمين والنماذج تُحرسان بصلاحيتهما عبر `enabled`.
- **D7:** كوكي قديم الشكل يعني أن `readSessionUser()` تعيد `null` **دون** مسح التوكنات، فيُجلب الملف ولا يُخرج أحد.
- **D9:** `QueryCache` و`MutationCache` في `query-client.ts`: عند `403` يُستدعى `invalidateQueries(users.me)`.
- **D11:** معرّفات المستخدمين `number`، كما في الدليل.

## القيود

- لا تبعيات جديدة. `Checkbox` مؤجَّل إلى المرحلة 5، ويُبنى على `<input>` أصلي.
- كل نص يراه المستخدم **بالعربية**.
- لا تعليقات إلا لسبب غير بديهي، سطر واحد. حدّث التعليقات التي صارت كاذبة، مثل «لا يوجد `/auth/me`» في `session.ts` و`use-session.ts` و`types/auth.ts`.
- لا إعادة هيكلة خارج ما تطلبه المراحل. لا مجلد `features/`، ولا Store جديد، ولا Context ثانٍ.
- الـ Backend هو الحَكَم. التفويض في الواجهة لتجربة المستخدم فقط.

## التنفيذ

### المرحلة 0: شغّل أوامر `curl` في الخطة

وثّق الأشكال الفعلية لـ`role` و`permissions`، ولـ`creator` داخل التقرير (الغموض A1)، ولغة رسائل `409` (A4).

- **إن خالف أي شكل الدليل: توقّف واسألني.**
- إن كان الـ Backend لا يعمل: أخبرني ولا تخمّن الأشكال.

### المراحل 1 → 4

نفّذها بالترتيب. بعد كل مرحلة:

```bash
npm run typecheck && npm run lint && npm run build
```

ثم commit مستقل، برسالة إنجليزية قصيرة بأسلوب سجل المشروع، تنتهي بسطر الـ Co-Authored-By المعتاد.

- المرحلة 1 وحدها ستكسر `typecheck` في مواقع الاستهلاك، وهذا متوقع. ضمّ المرحلتين 1 و2 في commit واحد إن لزم لإبقاء كل commit أخضر.
- **لا تدفع (push) ولا تفتح PR.**

## التحقق قبل أن تقول «انتهيت»

1. الأمر التالي لا يعيد أي نتيجة:

   ```bash
   grep -rn "'ADMIN'\|ROLE_LABELS\|UserRole\|allowedRoles\|RequireRole" src
   ```

   الاستثناء الوحيد المسموح: `BuiltInRole` في `types/role.ts`.
2. `typecheck` و`lint` (صفر تحذيرات) و`build` كلها ناجحة.
3. شغّل `npm run dev`، وأنشئ عبر `curl` دوراً «قارئ» بصلاحيات `REPORTS:["VIEW"]` فقط ومستخدماً به (القسم 10 من الدليل). ثم نفّذ من مصفوفة الاختبار في الخطة: **T1، T2، T5، T6، T10**.
   - إن لم تستطع فتح المتصفح، **قل ذلك صراحةً**. لا تدّعِ نجاح اختبار لم تُجرِه.
